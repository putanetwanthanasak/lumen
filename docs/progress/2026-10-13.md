### Open questions
1. `webhook_events.event_type` allows all six events from 03 section 2 (including `installment_overdue` and `cash_loan_created`), while 04 section 4.1 says "4 types". I chose the wider set so valid platform events aren't rejected.
2. The L41 fields `min_payment`, `late_fee_per_period`, `monthly_rate` are NOT NULL with no default, because L41 says the contract carries them. A default of 0 would make debt look free to the planner. Is that right, or should missing values be allowed for some event types?
3. I added a rule that an auto_save must have a `source_event_id`. Without it, an auto_save with NULL would slip past INV-3, since NULLs never collide in a UNIQUE index.
4. Rates are stored as `Numeric(7,6)`. Six places hold monthly rates such as 0.020833 (25% APR / 12) without rounding to cents.
5. I did not add the following, because each would be a spec decision. Should any of them be added?
   - An auto_save amount range (INV-4): the lower bound of 10.00 is enforceable, the upper bound depends on `per_item_cap` at the time.
   - A rule that `auto_save_enabled` requires `consent_at` (SV-02 implies that state is valid).
   - A notification dedupe key.
   - `updated_at` columns.
- INV-1 (balance equals the sum of transactions), INV-5 (no auto-save from cash events), and INV-7 (cancelling doesn't change savings) can't be expressed as column or table constraints. They're for `reconcile` and the service tests.
