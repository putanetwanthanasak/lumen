### Bugs found
1. **A break test that could not fail (B1, first run).**
   - **Root cause:** the test DB was already at head, so an edited migration never re-ran. Rerunning it with the test DB downgraded first exposed a real gap: `Base.metadata` was empty in `test_app_role.py` because `app.models` was never imported, so the per-table test ran 0 cases (shown only as "1 skipped").
   - **Fix:** import `app.models`, plus `test_S2_every_table_is_checked`. CI always starts from a fresh DB, so it was never affected by the first part.
2. **The S4 race test could not see a missing lock (B11).**
   - **Root cause:** the mock platform answers instantly, and the first-report UPDATE in `dispute()` takes a row lock that already serializes the taps. The lock in `send_signal` only matters while the platform call is in flight.
   - **Fix:** the race now uses a platform that takes 0.2 s, plus a deterministic probe (`test_S4_send_signal_waits_for_the_contract_lock`). Without the lock both fail 10/10.
3. **A false pass in the S1 test, found while writing it.** `session.rollback()` after the lost commit also rolled back the user's consent row, so the retry saved nothing, and "debited once" held for the wrong reason. The test now commits consent first and asserts the retry saves exactly 120.00.
4. **`hide_parameters` was not enough (S12), found by the first S12 test.**
   - **Root cause:** Postgres's DETAIL ("Failing row contains (...)") quotes the user ref and the alert body.
   - **Fix:** `describe_db_error` (class, SQLSTATE, constraint) in the 500 handler and the push step, proven by the webhook and push log tests (B4, B5).
5. **A test-DB mix-up during B16.** My break renamed the constraint, so the restore downgrade failed and left `lumen_test` at head with the broken CHECK. I repaired it by hand (owner role, test DB only) and the full suite passed again. No code change was needed.
