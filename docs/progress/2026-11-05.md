## Session 23, PR 3: a retried auto-save records what the bank already moved

Branch `fix/auto-save-retry-guard` from origin/main, opened after PR 2 as the user ordered. The rest of Session 23 (the scoped money review, PR 1 and PR 2) is logged in those PRs. Whichever of PR 1 and PR 3 merges second will need its log rebased.

### Done
- **Scoped money review F2 (medium, existed before #48).**
  - The auto-save transfer runs before COMMIT. When the commit was lost, the retry decided the saving again from a bank balance that already reflected it.
  - Near the 500.00 safety net the retry saved 0.00, while the money had left the main account with no row for it.
  - After a rule change, the retry asked the bank for another amount under the same key: refused, so every retry was a 500, and on the webhook path the installment and its new-debt alert were never recorded.
- **Fix:** `savings.auto_save` takes the caller's `transfer_key`.
  - It asks `bank.applied_to_savings(user, key)` first. If money already moved, it records that amount, as payday does with its leftover (`payday/service.py:77`).
  - The amount is recorded even if auto-save was turned off in between (the user's answer: never lose money).
  - The callers pass the key they already used: `manual_transfer_key` in `installments/service.py`, and `transfer_key` in `webhooks/processor.py`.
  - The first attempt is unchanged.
