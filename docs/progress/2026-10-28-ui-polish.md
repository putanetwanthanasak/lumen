### Bugs found
1. **The nav check leaked state between views** (while committing it, your answer 13).
   - **Symptom:** the first full run failed 16 views. Every 370px view after the 390px `demo-panel-open` view had something else on top at every point.
   - **Reproduced:** the 370px views alone passed (74,276 points).
   - **Root cause:** going from one view's URL to the next changed only the `#`. Chrome kept the same document, so the Demo panel opened in the last 390px view (a `z-30` dialog over the frame) stayed open over every later view.
   - **Fix:** each view goes through `about:blank` first. The script checks that Chrome answers with a `loaderId`, which it gives only for a new document.
   - **Proof:** the full run then passed: 102 views, 3,220,724 points.
2. **The nav check's cleanup raced Chrome.**
   - **Symptom:** one run in 10 ended with `ENOTEMPTY: directory not empty, rmdir '/tmp/nav-layer-check-.../Default'`.
   - **Root cause:** Chrome's network service (`utility:network`) can outlive the main process by a few milliseconds. As it quits, it writes `Default/Network Persistent State` into the profile, and the script deleted the profile as soon as the main process exited.
   - **Evidence:** a scan of `/proc` found the network service still alive at "exit" in 6 of 30 runs. Waiting for "exit" still failed 5 of 30.
   - **Fix:** wait for the child's "close" event. It comes once every process holding Chrome's output is gone, 6 to 13 ms after exit. A 10-second limit leaves the profile in place and says so.
   - **Proof:** 0 of 30 failures with "close", and no profile left after this follow-up's full run. Three profiles left by my earlier runs were removed.
3. **A month split from its year at a line break.** My browser check of this follow-up's own changes found it before commit:
   - **Symptom:** the hero's warning broke as "มิ.ย. / 2570" at 370px, and the schedule as "ธ.ค. / 2569".
   - **Root cause:** Thai has no spaces between words, so the space inside "มิ.ย. 2570" is one of the few places a line can break.
   - **Fix:** `KeepMonths`, and the schedule's whole parts (Done 7).
   - **Proof:** UI-41's `KeepMonths` test and UI-43's markup test; B-UI-167 and 168.
4. **Two of my new tests were wrong at first.** Both failed on correct code, and I fixed the tests, not the code:
   - **The UI-42 scan for inner boxes** counted the hero card's own shadow. It now scans only the elements inside the card.
   - **The UI-40 budget line** expected 60%. In that fixture the budget is the top of the scale, so 100% is right, and the test now says why.
5. **My 370px screenshot of the open paid-off list showed it closed.** The file was byte for byte the closed one.
   - **Root cause:** the 370px frame is 844px tall, and my screenshot script clips to the frame. The opened list is further down, inside the scrolling body.
