### Bugs found
1. **The form's header and nav were mounted twice (new in this follow-up, caught in self-check before the commit).**
   - **Reproduced:** a browser check sampled the page every 50ms after tapping into the form (`remount.mjs` in the session scratchpad).
     - With the first structure, the form appeared at 950ms with a new `<header>` and `<main>`, and the bell's badge disappeared until 1400ms. That is a 450ms flicker, and anything focused in the header or nav would have lost focus.
     - After the fix, the header and main stay the same nodes from loading to the form, and the badge stays.
   - **Root cause:** for the bar, the ready form rendered its own `Screen`, while the loading state's `Screen` came from `ThinkFirstScreen`. A different parent at the root made React remount the whole shell, and with it the bell, which loads `GET /notifications` again.
   - **Fix:** `ThinkFirst` takes the load state and returns a `Screen` from every branch, so React keeps one instance. The deep-link preview still waits for the settings.
   - **Proof:** the browser check above. Server rendering cannot see a remount, and there is no DOM library in the project. `UI_37_before_the_form_is_ready_the_same_screen_shows_no_check_bar` covers the states that `ThinkFirst` now draws.
