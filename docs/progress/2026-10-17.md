#### Bugs found
1. **A blind spot in my race test, found by its break test.**
   - **Symptom:** with the lock removed, the payment-race test failed 20/20 when run after another test in the file, but 0/30 when run alone.
   - **Root cause:** a cold connection pool. Opening two new DB connections staggers the two requests enough that the payment always finishes before the tap starts.
   - **Evidence:** the failure was `(800, 'paid_off') != (800, 'disputed')`, the lost update the lock prevents.
   - **Fix:** the test warms two pooled connections first. Without the lock it now fails 20/20 alone; with the lock it passes 20/20. The deterministic probe (`test_L42_dispute_waits_for_the_contract_lock`) does not depend on timing at all.
2. **A race prevented before it shipped** (found while planning, proven by break test 5). Without the contract lock, a payment that read `active` could run `_settle` after a dispute committed and write `paid_off` over `disputed`.
